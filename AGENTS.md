# Guide for reviewers

This file lists the files of this repository, each claim of `README.md` and `REPORT.md` with the files that hold its evidence, and the commands that check it (`SPEC.md` §8.3). It changes no analysis.

## What this repository is

A pre-registered test of one question (`SPEC.md` §0, `PREREG.md` §1): after spinal anesthesia, do heart rate and the pulse-oximeter (pleth) waveform improve the forecast of the next cuff reading (MAP) beyond the cuff readings alone? The models are fitted on the non-cesarean spinal cases in VitalDB (S-dev: 252 cases, 203 analysed, cross-validated), then scored once, frozen, on the spinal cesarean cases in VitalDB (S-ob: 21 cases, 19 analysed, an external case series that cannot change the answer). The primary outcome is Δ, the patient-level mean RMSE of M4 (cuff, heart rate and waveform features) minus that of M2 (cuff-only third-order model), for the next reading in the first 30 minutes (`SPEC.md` §6.2). A contrast "meets the rule" if, in S-dev, its relative reduction is at least 5% and the upper 95% CI limit of Δ is below zero (`SPEC.md` §6.3); the headline sentences are then chosen mechanically from a pre-written table. The registration is `PREREG.md` and `SPEC.md`, version 1.5, commit `59939b7` (tag `prereg-v1.5`); where they disagree, `PREREG.md` wins.

## Commands

Environment (Python 3.13 and the exact packages of `uv.lock`, in `.venv`; `pytest` is in the `dev` group, which `uv sync` installs by default; torch, in the `encoder` group, is not installed by default and is not needed by `scripts/verify.py`):

```
uv sync --locked
```

Check the public record (offline, no download, a few seconds; fits no model and writes no file):

```
uv run python scripts/verify.py           # text: PASS / FAIL / SKIPPED per check, with the files used
uv run python scripts/verify.py --json    # the same as JSON
```

The checks: 1 registration hashes, tags and their order; 2 manifests; 3 frozen models and the one cesarean scoring; 4 recomputation of the headline numbers and sentences from the per-patient tables with the project's bootstrap (`btc/models/bootstrap.py`; 2,000 subject resamples, seed 20261118) and sentence code (`btc/models/headline.py`), and the contrasts of the exploratory encoder check where its results exist; 5 `README.md` and `REPORT.md` against the result files; 6 data checksums; 7 public-data rule. The exit code is 0 if no check fails. If `README.md` is the interim version written before the cesarean scoring, check 5 reports its README items as SKIPPED. `--root <clone>` checks another clone.

Test suite (no network; some tests use git and a temporary clone; tests that need torch or the encoder weights are skipped without them):

```
uv run pytest -q
```

Full rerun from the public VitalDB API, comparing every result file with its published SHA-256 (network; about 1.7 GB from VitalDB and 23 MB of encoder weights from Zenodo; the `encoder` group adds the CPU build of torch; see `scripts/reproduce.py --help`):

```
uv run --locked --group encoder scripts/reproduce.py
```

Single steps and their order: `results/README.md`, "Regenerating the withheld files".

Git commands for the registration record (dates in their output are set by the author's clock):

```
git tag -n20                                                  # the three tags and their messages
git log --oneline --decorate                                  # history with the tags
git diff prereg-v1.5 HEAD -- PREREG.md SPEC.md                # empty: registration unchanged
git ls-tree -r --name-only feature-freeze -- results          # empty: no result file at the feature tag
git log --diff-filter=A --format='%h %s' -- results/sob/frozen_scoring/summary.json
git diff --stat feature-freeze models-frozen                  # what changed between the two tags
git tag -l --format='%(contents)' models-frozen               # SHA-256 of the frozen models
```

One number by hand, Δ of M4 vs M2 in S-dev with its 95% CI (`results/README.md`, "Per-patient tables", gives the recipe); run from the repository root inside the environment (`uv run python`):

```python
import pandas as pd
from btc.models.bootstrap import SubjectBootstrap, contrast
w = pd.read_csv("results/sdev/confirmatory/per_patient_primary_wide.csv", skiprows=1)
e = w[w.entered].sort_values("caseid")                        # patients with at least 3 forecasts
bs = SubjectBootstrap(e.caseid, e.subjectid, 2000, 20261118)  # resamples subjects
print(contrast(bs, e["rmse_M4"], e["rmse_M2"], "M4", "M2"))   # = "M4 vs M2" in summary.json
```

## What is not in the repository and why

- **Per-forecast result files**: the five that `results/README.md` lists (`predictions_primary.csv` and `yardstick_predictions.csv` of `results/sdev/confirmatory/` and `results/sob/frozen_scoring/`, and `predictions_primary.csv` of `results/sob/frozen_scoring/sensitivity_including_nmb/`), and `predictions_primary.csv` of the two `exploratory_encoder/` folders. They hold, for every forecast, the cuff value it targets (`y_map`) and the last cuff value before it (`last_map`), with the case ID and the reading times, so they reproduce part of the VitalDB cuff track. They are git-ignored; their SHA-256 are in the `MANIFEST.json` of the run that wrote them. The per-patient tables (`per_patient_primary_wide.csv`, `per_patient_yardstick.csv`) are published in their place, with `public_tables.json` naming each source file and its SHA-256 (`results/README.md`, "Per-patient tables").
- **`results/sdev/secondary/coefficients_all_sdev.csv`**: listed in `results/sdev/MANIFEST.json`, omitted for its labelling. Its `penalty` column repeats each stage's own penalty on every row (code at tag `feature-freeze`). Its coefficients equal those of chain `main` in `results/frozen/coefficients.csv`, which is the registered coefficient table (`results/README.md`, "One coefficient table, omitted for its labelling").
- **Encoder weights and embeddings**: the PaPaGei-S weights are downloaded at run time by `scripts/download_encoder.py` and not redistributed (`REPORT.md`, "Exploratory pretrained-encoder check"); the embeddings are derived from VitalDB signals and not published (`results/README.md`).
- **Raw VitalDB data and derived tables** (`data/`): downloaded from the public API at run time under CC BY 4.0 and the VitalDB Data Use Agreement (`SPEC.md` §2.1). `results/data_checksums.csv` lists the SHA-256 of every stored array, with no data.
- **Per-case series of the case browser and the replays** (`data/derived/site/`): VitalDB-derived and git-ignored; the web page holds pre-rendered images.
- **Local logs**: the download request logs (request times) and local file times are not committed. `REPORT.md` cites them as the author's record.

## Known limits of the record

- **Git dates are set by the author.** Commit and tag dates come from the author's clock and can be rewritten; git ancestry shows order only. Times set by GitHub's server: the `published_at` time of each release (releases page or API) and the push events on the activity page, both in UTC.
- **The single cesarean scoring rests on plain files.** `results/sob/frozen_scoring/STATE.json` and `results/sob/frozen_scoring_log.jsonl` are written by `scripts/run_frozen_scoring.py`, which refuses a second run once `STATE.json` records a completed one. Git and GitHub show when these files were committed and pushed, not how often the script ran.
- **Byte identity depends on the platform.** A rerun at the same commit on the same inputs gives identical bytes on the same platform; on another CPU or numerical library the last digits, and so the SHA-256, can differ. Compare the numbers then (`results/README.md`, first paragraph).
- **What `verify.py` recomputes.** It recomputes from the per-patient tables; the per-patient RMSE come from the withheld per-forecast files and were checked against them when exported (`public_tables.json`, `checks`). The secondary analyses, the gradient-boosting arms and the hypotension tables need a rerun.
- **Scope of check 7.** It reads CSV headers and file types; it does not inspect images, HTML or JSON files.

## Exploratory encoder check

Plan: `ENCODER_PLAN.md`, committed and pushed (commit `29db44b`) before any encoder output was computed; every encoder result file records the plan's SHA-256 and that commit (`meta.plan`, `meta.plan_public`). Results: `results/sdev/exploratory_encoder/` (build check at `a07e0d2`, S-dev run at `d66ad63`) and `results/sob/after_frozen_scoring/exploratory_encoder/` (cesarean step, run once at `dda1d6d`, after the frozen scoring); `REPORT.md`, "Exploratory pretrained-encoder check", lists them with the disclosures and departures. The contrasts are recomputed from the committed per-patient tables by verify 4. The embeddings, the build check and the per-forecast files need a rerun (stages `encoder` and `encoder-sob` of `scripts/reproduce.py`).
